# 05 · 后端原型：两种方案的对比

> 目的：回答"静态网页没法录入数据"该怎么办。
> 结论：**同一份前端，两种后端可选**，你看到实物再决定。

---

## 怎么跑起来

```bash
cd 05-后端原型 && python3 -m http.server 8090
# 打开 http://localhost:8090
```

页面顶部可切换 **A / B** 两种模式，功能完全一样，区别只在数据存哪。

---

## 方案 A：仅本地（零后端）

**现在就能用，一行后端代码都不需要。**

| 维度 | 情况 |
|---|---|
| 成本 | 0 元 |
| 上线时间 | 现在 |
| 断网 | ✅ 完全可用 |
| 合规风险 | ✅ 几乎为零（数据没离开设备） |
| 你能看到数据吗 | ❌ 看不到任何家庭的 |
| 换设备 | ❌ 数据不会跟过去 |

**适合**：先验证"这套方法孩子愿不愿意用"。

---

## 方案 B：云端（Cloudflare Worker + D1）

数据存 Cloudflare，多设备同步，你（运营方）能看到使用情况。

| 维度 | 情况 |
|---|---|
| 成本 | 0 元（免费额度内） |
| 上线时间 | 约 1-2 周 |
| 断网 | ✅ 本地缓存 + 恢复后补传 |
| 合规 | ⚠️ 需承担未成年人数据责任（已内建措施，见下） |
| 你能看到数据吗 | ✅ 可以 |
| 换设备 | ✅ 自动同步 |

### 免费额度（Workers Free，官方定价页实测）

| 项 | 额度 |
|---|---|
| 行读 | 500 万 / 天 |
| 行写 | 10 万 / 天 |
| 存储 | 5 GB |
| 计费 | 无查询时不计费（scale-to-zero） |

> 10 万行写/天 ≈ 每个家庭每天可写约 1000 条。**几千个家庭规模内够用。**

### 部署步骤

```bash
npm install -g wrangler
wrangler login
wrangler d1 create learnos-db          # 记下返回的 database_id
# 把 id 填进 wrangler.toml
wrangler d1 execute learnos-db --file=./schema.sql --remote
wrangler deploy
```

首次还要在库里插一个家庭码：

```bash
wrangler d1 execute learnos-db --remote \
  --command="INSERT INTO families (id,code,created_at) VALUES ('fam1','FAM-你的码',unixepoch()*1000)"
```

## 为什么要做"契约解耦"

```
        ┌─────────────────┐
        │   前端（同一份）  │
        └────────┬────────┘
                 │ 只认 contract.js 定义的接口
        ┌────────┴────────┐
        │                 │
   LocalAdapter      HttpAdapter
   （浏览器）         （云端）
```

`contract.js` 是**单一事实来源**：间隔算法、数据形状、接口签名都在这里。

**好处**：先上 A 验证方法有效性，需要时切换 B —— **前端业务代码一行都不用改**。

---

## 合规措施（已内建，因为你选了"面向很多家庭"）

| 要求 | 实现 |
|---|---|
| 不收集真实身份 | 只存昵称，`consent-notice` 明确声明绝不收集姓名/手机号/身份证 |
| 家长同意 | 创建档案必须 `consent: true`，否则 403；同意时间落库 |
| 数据可携带 | `GET /api/kids/:id/export` 全量导出 |
| 数据可删除 | `DELETE /api/kids/:id` **物理删除**（非软删） |
| 越权防护 | 每个请求校验孩子归属本家庭，否则 404 |
| 最小留存 | 不记录 IP / UA 到业务表 |
| 令牌时效 | 30 天过期，可撤销 |

> ⚠️ 仍建议你正式上线前咨询一次儿童个人信息保护的合规意见。
> 我做的是"技术措施到位"，不等于"法律意见"。

## 建议

**先 A，后 B。**

理由：你现在还没有真实用户。B 是 1-2 周的工作量，但**验证不了任何新东西**——
你真正需要先知道的是"这套方法孩子愿不愿意用"。

等 A 跑出真实反馈（哪个动作孩子抗拒、哪个有效），再决定要不要上 B。
